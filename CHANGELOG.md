# Changelog

Release-owned: pull requests do not edit this file. Release notes go in the
pull request body, which becomes the squash commit; at release,
`scripts/changelog-draft.sh` lists the merged changes since the last tag.
GitHub Release notes come from the matching version section.

The format is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.1.1-rc.1] - 2026-11-13

Patch release candidate after 0.1.0. Proto, WAL, snapshots, and `EZU_*`
settings are unchanged. JWT callers keep the same JWKS file. The release
image is also published at `ghcr.io/sannrox/ezu:<version>` (version tag
only; deploy by digest). Query and event contracts stay `0.1.0`.

### Added

- A Tenkai product that installs the digest-pinned release image and
  declares `ezu.query` 0.1.0 and `ezu.events` 0.1.0 for dependents.
  Operators supply `ezu.env` and the files it names in the workdir.

### Changed

- Tagged releases run from `main`. A `vX.Y.Z-rc.N` or `vX.Y.Z-beta.N` tag
  publishes as a GitHub pre-release and is never marked latest.
- JWT signatures are verified with `ring`, already used for TLS, instead
  of jsonwebtoken's `rust_crypto` backend.

### Fixed

- Family-release gate flags count only pull requests whose merge is in
  the tagged range.

### Security

- `deny.toml` no longer ignores RUSTSEC-2026-0387 or RUSTSEC-2023-0071.
  JWT verification no longer depends on `crypto-bigint` 0.5 or the `rsa`
  crate.

## [0.1.0] - 2026-11-02

First tagged release, prepared for signature and immutable release verification.
The release includes a binary, an image archive, an SBOM and provenance.
Verify the published release with `git verify-tag v0.1.0` and
`gh release verify v0.1.0` before using it.

### Fixed

- Release SBOMs carry a valid document identity and license expressions.

### Added

- Spatial indexing, geofences, recent tracks and bulk data interfaces.
- Durable write logging, encrypted snapshots and fenced replica promotion.
- Versioned diagnostics and documented configuration compatibility.

## [0.0.0]

Initial development crate version before the first tag. The crate is not on crates.io
(`publish = false`). `Dockerfile` builds the release image from the static
binary; deploy by digest, never by a `latest` tag.
